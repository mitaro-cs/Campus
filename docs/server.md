# Campus на своём сервере

Сайт работает круглосуточно и не зависит от компьютера хоста. Нужен VPS (виртуальный сервер)
с Linux. Cloudflare Pages, Vercel и Netlify **не подойдут**: они отдают только готовые страницы,
а Campus – это Java-сервер с базой и файлами на диске.

## 1. Сервер и адрес

- **VPS**: Ubuntu 24.04 (или 22.04, Debian 12), от 1 ядра, **2 ГБ памяти**, 20 ГБ диска и больше
  под файлы группы.
- **Адрес**: домен с A-записью на IP сервера (`campus.example.ru → 203.0.113.7`). Если домен
  в Cloudflare – запись «Только DNS» (серое облако), хотя бы на время установки. Домена нет –
  подойдёт `203-0-113-7.sslip.io` (IP через дефисы), ничего настраивать не нужно.
- Порты **80** и **443** открыты (в панели хостинга, если там свой файрвол).

### Бесплатно

- **Oracle Cloud Always Free** – лучший вариант: сервер ARM (Ampere) до 4 ядер и 24 ГБ памяти,
  200 ГБ диска, бессрочно. При регистрации нужна банковская карта (не списывают; российские не
  принимают). Образ – Ubuntu 24.04, форма VM.Standard.A1.Flex (2 ядра, 12 ГБ хватит с запасом).
  В сети облака (VCN → Security List) откройте входящие TCP 80 и 443; внутри сервера их откроет
  скрипт. Простаивающие бесплатные машины Oracle может забрать – перевод аккаунта в Pay As You Go
  это снимает (в пределах Always Free по-прежнему 0 ₽), а копии пусть уходят к вам.
- **Google Cloud Free Tier** – e2-micro в США (1 ГБ памяти, 30 ГБ диска), тоже с картой. Работает,
  но впритык: скрипт сам добавит подкачку.
- **Свой компьютер** – приложение хоста (бесплатно, туннель встроен) или старый ноутбук / мини-ПК с
  Linux. Минус – сайт работает, пока компьютер включён и в сети.
- Render, Railway, Koyeb, Vercel, Cloudflare Pages бесплатно **не подходят**: засыпают и/или не
  хранят файлы – база пропадёт.

Адрес бесплатно – `IP-через-дефисы.sslip.io` (выше), домен `.ru` – около 200 ₽ в год.

## 2. Перенос данных группы

На компьютере хоста: **Управление → Сервер → «Сделать копию сейчас»**, затем у свежей копии –
значок «Скачать копию» (или «Открыть папку»). В архиве всё: база, файлы, ключи шифрования.
Скопируйте его на сервер (Windows – в PowerShell, Mac – в Терминале):

```bash
scp campus-копия.zip root@203.0.113.7:/root/
```

## 3. Установка – одна команда

```bash
ssh root@203.0.113.7
curl -fsSL https://raw.githubusercontent.com/mitaro-cs/Campus/miaro/deploy/server/install.sh \
  | CAMPUS_RESTORE=/root/campus-копия.zip bash -s -- campus.example.ru
```

Без `CAMPUS_RESTORE=…` – чистый сайт: в конце будет ссылка `https://…/setup?code=…`, там можно
создать группу или «Восстановить из резервной копии».

Скрипт ставит Java 21 и Caddy (сертификат HTTPS получит и продлит сам), заводит службу
`campus` (поднимается после сбоя и перезагрузки, память – до 512 МБ), ежедневная копия – в 03:30,
14 последних.

## 4. После переноса

- **Выключите приложение на компьютере хоста** (или удалите его из автозапуска) – иначе по старому
  адресу останется второй сайт, и изменения разойдутся.
- Разошлите группе новый адрес. На телефонах установите сайт заново («На экран Домой»)
  и снова включите уведомления – они привязаны к адресу.
- **Ключи входа** (passkeys) привязаны к адресу сайта: на новом входят по паролю и добавляют ключ
  заново в «Профиле». Пароли, 2FA, файлы, роли – переезжают как есть.

## Обслуживание

| Что | Команда |
|---|---|
| обновить до последнего выпуска | `sudo bash /opt/campus/update.sh` (копия → новая версия → не поднялась – откат) |
| журнал | `journalctl -u campus -f` |
| перезапуск | `sudo systemctl restart campus` |
| настройки | `/etc/campus.env` (переменные – README, «Свой сервер»), затем перезапуск |
| копия вручную | `sudo runuser -u campus -- java -jar /opt/campus/groupbase.jar backup -d /var/lib/campus/data` |
| проверить данные | `sudo runuser -u campus -- java -jar /opt/campus/groupbase.jar doctor -d /var/lib/campus/data` |

Копии лежат в `/var/lib/campus/data/backups` и скачиваются из «Управления». Хранить их только на
том же сервере – рискованно: раз в неделю скачивайте свежую к себе.

**Восстановить копию на работающем сервере:**

```bash
sudo systemctl stop campus
sudo runuser -u campus -- java -jar /opt/campus/groupbase.jar restore -d /var/lib/campus/data /root/копия.zip
sudo systemctl start campus
```

Прежние данные остаются рядом, в `before-restore-…`.
