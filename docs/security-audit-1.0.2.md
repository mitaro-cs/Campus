# Аудит безопасности Campus 1.0.2

Проверка собственного кода перед выпуском 1.0.2: что могло бы позволить чужому человеку (или
участнику группы) увидеть или изменить то, что ему не положено, или помешать сайту работать.
Метод – чтение кода всех 265 ручек API, проверка на запущенном сервере (обычный режим и режим
приложения хоста) и регрессионные тесты: каждое исправление закреплено тестом, который упадёт, если
дыра вернётся.

## Итог

| # | Что | Важность | Статус |
|---|-----|----------|--------|
| 1 | «Только с этого компьютера» держалось на адресе 127.0.0.1 – туннельный клиент на компьютере хоста подключается к серверу с того же адреса | Высокая | Исправлено |
| 2 | Разбор текста документов (поиск в файлах): презентация из тысяч крупных частей могла занять всю память | Средняя | Исправлено |
| 3 | Один аккаунт мог открыть сколько угодно потоков живых обновлений и занять соединения сервера | Средняя | Исправлено |
| 4 | Перенаправление после входа: адрес с табуляцией или переводом строки уводил на чужой сайт | Низкая | Исправлено |
| 5 | PDF разбирался целиком в памяти | Низкая | Исправлено |

Изоляция групп, права, загрузка и раздача файлов, санитайзер Markdown, cookie, CSRF, web push,
поиск, резервные копии – проверены, нарушений не найдено (подробности – ниже).

## Найдено и исправлено

### 1. Окно хоста и туннель (высокая)

**Где.** `web/Requests.fromThisComputer`: ручки «только с этого компьютера» – первый запуск, выбор
папки данных, перенос и связь компьютеров, экран ожидания, локальная сессия окна хоста без 2FA –
доверяли запросу, если адрес клиента – 127.0.0.1.

**Почему опасно.** Клиент туннеля (fxTunnel, CloudPub) работает на том же компьютере и подключается к
серверу с 127.0.0.1. Настоящий адрес участника сервер узнаёт, только если туннель передаёт его в
`X-Forwarded-For`; это зависит от сторонней программы и в коде нигде не проверялось. Без этого
заголовка любой, кто знает адрес сайта, выглядел бы для этих ручек как окно хоста. На
работающем сервере это было видно по `GET /api/setup`: по основному порту он отдавал путь к
каталогу данных – признак «локального» запроса.

**Исправление.** Окно хоста теперь работает на отдельном порту: второй вход Tomcat только на
127.0.0.1 (`web/WindowConnector`, `groupbase.desktop.window-port`, порт выбирает `DesktopCommand`).
Туннель и локальная сеть ведут на основной порт, и «с этого компьютера» теперь означает «пришло на
порт окна» (`Requests.windowPort`). Оболочке менять ничего не пришлось: адрес окна она берёт из
события `ready`.

**Проверено.** `RequestsTest.withAWindowPortOnlyThatPortIsThisComputer`. На собранном jar в режиме
приложения: основной порт – `{"needed":true}` без пути к данным, порт окна – с путём. Из локальной
сети порт окна недоступен.

### 2. Память при разборе документов (средняя)

**Где.** `files/FileText` (1.0.2, поиск по содержимому файлов) складывал в память все нужные части
архива docx/pptx/xlsx, каждую до 20 МБ.

**Исправление.** Общий предел на все части – 64 МБ, не больше 2000 частей (`MAX_TOTAL`,
`MAX_PARTS`). Тест `FileTextTest.manyHugePartsStopAtTheTotalLimit`: 3000 слайдов – текст
извлекается, память не растёт.

### 3. Потоки живых обновлений (средняя)

**Где.** `sync/LiveUpdates.subscribe` – без предела на человека.

**Исправление.** Не больше 8 потоков на аккаунт (телефон, компьютер, несколько вкладок – с запасом),
лишние – самые старые – закрываются. Тест `LiveIT.oneAccountCannotHoardStreams`.

### 4. Перенаправление после входа (низкая)

**Где.** Страница входа проверяла `?next=` по первым символам. Браузер выбрасывает из адреса
табуляцию и переводы строк, и проверенная строка после этого могла стать адресом другого сайта.

**Исправление.** `lib/auth/next.ts safeNext`: адрес разбирается как в браузере, принимается только
свой сайт. Тест `next.spec.ts` (табуляция, перевод строки, `//`, `/\`, `javascript:`).

### 5. PDF в памяти (низкая)

PDFBox теперь держит буферы во временных файлах (`IOUtils.createTempFileOnlyStreamCache`), а не в
памяти.

## Проверено, нарушений нет

- **Изоляция групп.** Новый тест `GroupIsolationIT.contentOfAnotherGroupIsNeitherVisibleNorChangeable`:
  староста группы A по номерам пытается прочитать, изменить и удалить в группе B предмет, задание,
  новость, материал, файл (и его HTML), комментарии, архив семестра, реакции – везде 403/404. В
  общих списках, поиске, офлайн-копии (`/api/sync`), «Сегодня» и «кто на сайте» чужого нет. Чужой
  загруженный файл нельзя прикрепить к своему материалу. Всё у группы B после попыток на месте.
- **Права.** Проверки – в `@Require` или в сервисах (`Authz`, `Access`); прежние тесты
  `GroupIsolationIT`, `RbacMatrixTest` и тесты разделов зелёные. Новые ручки 1.0.2 (реакции, архив
  вручную, второй диск, замеры скорости, мониторинг) проверяют видимость и права так же.
- **Файлы.** Inline отдаются только PDF и растровые картинки, с `Content-Security-Policy: sandbox`;
  SVG и HTML – только скачиванием. Размер ограничен по реальным байтам, а не по заголовку. Имя
  очищается (`Mime.safeName`), `Content-Disposition` собирается библиотекой.
- **Картинки.** Размер проверяется до декодирования (от 16 до 8000 точек) – «бомба» 20000×20000 не
  распакуется.
- **HTML.** Markdown (новости, задания, правила, конспекты) проходит через OWASP HTML Sanitizer;
  подсветка в поиске приходит частями, а не HTML.
- **Поиск.** Синтаксис FTS5 в запросе – только текст: кавычки, скобки, `NEAR`, `OR`, `*`, `^`,
  нулевой символ, 5000 знаков – без ошибок сервера (`SearchIT.oddQueriesNeverBreakTheSearch`).
- **Вход и сессии.** Cookie `HttpOnly; SameSite=Strict`, Secure по схеме запроса; CSRF – двойная
  отправка; ключи компьютеров и коды сравниваются за постоянное время (`MessageDigest.isEqual`);
  пароли – Argon2id; подбор пароля и кода входа ограничен.
- **Web push.** Сервер шлёт только на домены служб push из списка и только по https.
- **Копии.** Имя копии в адресе проверяется по шаблону; распаковка не выходит за каталог данных
  (`BackupIT.zipSlipIsRefused`); второй диск – только из найденных, путь из браузера не
  принимается.

## Что остаётся на будущее

- **Ключи в копиях.** Копия содержит ключи шифрования файлов – так задумано (без них копия
  бесполезна). Флешку с копиями нужно хранить так же бережно, как сам компьютер; об этом говорит
  предупреждение в «Резервных копиях».
- **Время разбора документов.** Память ограничена, но очень сложный PDF может долго занимать один
  фоновый поток индексации. Сайт от этого не тормозит (поток виртуальный и один), но следующий файл
  ждёт. Можно добавить предел по времени.
- **Сторонний туннель.** После исправления 1 поведение туннеля (передаёт ли он адрес участника)
  на безопасность не влияет – полезно лишь для журнала и ограничения попыток входа по адресу.
